## 2024-05-18 - React Static Configs vs Garbage Collection
**Learning:** In a highly interactive UI like the Dashboard, large static configuration objects defined *inside* render functions (e.g., `styles`, `labels`, `dotColors` in `StatusBadge`) are recreated on every single render. This introduces measurable overhead and garbage collection pressure when the component is re-rendered frequently. Similarly, computing complex nested state (like mapping `navGroups` and checking `pathname` active states) inline on every render is inefficient.
**Action:** Always move static, read-only configuration objects and mapping arrays outside of the component render function. For derived state that depends on props (like checking if a route is active against `pathname`), wrap the computation in `useMemo` so it only re-runs when dependencies actually change.
